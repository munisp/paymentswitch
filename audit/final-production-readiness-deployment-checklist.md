# Final Production Readiness Deployment Checklist

**Author:** Manus AI
**Decision model:** Fail closed. Any unchecked required item means **NO-GO**.
**Evidence lifetime:** Live evidence must be no older than 24 hours unless an approved release policy specifies a stricter limit.

## 1. Release identity and source integrity

| Required check | Acceptance criterion | Evidence |
|---|---|---|
| Release commit | Exact lowercase 40-character Git commit from protected `main` | `git rev-parse HEAD` |
| Clean source | No uncommitted production changes | `git status --porcelain` returns empty |
| Lockfile integrity | SHA-256 of `pnpm-lock.yaml` recorded in the evidence manifest | `sha256sum pnpm-lock.yaml` |
| Immutable image | Runtime image referenced by `sha256:<64 hex>` digest, not a mutable tag | Registry digest and deployment manifest |
| Reproducible dependencies | Frozen lockfile install succeeds | `pnpm install --frozen-lockfile` |
| Software bill of materials | SBOM generated for application and container image | CycloneDX/SPDX artifact |
| Signature/provenance | Image signature and build provenance verified | Cosign/SLSA evidence or enterprise equivalent |

## 4. PostgreSQL gate

- [ ] Production database uses a supported PostgreSQL release with TLS enforced.
- [ ] Separate least-privilege roles exist for migrations, API runtime, background workers, Keycloak, and Temporal.
- [ ] Migration `up` and rollback/recovery procedures were rehearsed against a production-like copy.
- [ ] Drizzle migrations apply successfully from the immutable release artifact.
- [ ] Tenant predicates are present in payment, settlement, remittance, onboarding, and reporting queries.
- [ ] Unique constraints enforce idempotency and business keys where required.
- [ ] Query plans for critical payment paths use approved indexes.
- [ ] `statement_timeout`, lock timeout, pool size, and connection lifetime are set per workload.
- [ ] Point-in-time recovery, backup restoration, and failover were tested.
- [ ] Database audit logging and privileged-role monitoring are enabled.

## 5. Keycloak identity and MFA gate

- [ ] Realm import/configuration is version-controlled and reviewed.
- [ ] Production clients use approved authorization flows; direct password grants are disabled.
- [ ] Access tokens use RS256 or the approved asymmetric algorithm.
- [ ] Issuer, audience, expiration, not-before, and signature are verified by gateway and backend.
- [ ] `tenant_id` originates from trusted identity data and cannot be overridden by request headers.
- [ ] Administrative roles require a verified MFA/ACR claim.
- [ ] Brute-force protection, lockout, password policy, session lifetimes, and token lifetimes are approved.
- [ ] Service accounts are least privilege and have rotation owners.
- [ ] Login, logout, token, administrative, and impersonation events are exported to the SIEM.
- [ ] Key rotation and previous-key overlap were tested without accepting unknown keys.

## 6. APISIX, OPA, Permify, Caddy, and OpenAppSec gate

- [ ] Caddy or the approved edge terminates modern TLS and forwards only trusted proxy headers.
- [ ] OpenAppSec policy is enforced in blocking mode after staged tuning.
- [ ] APISIX verifies OIDC before forwarding protected requests.
- [ ] APISIX-to-OPA communication uses mTLS or an equivalently authenticated private channel.
- [ ] OPA is deny-by-default and rejects malformed/missing tenant, subject, action, and resource context.
- [ ] OPA outage returns 503/deny and never bypasses authorization.
- [ ] Permify schema `paymentswitch_v1` is loaded through the ArgoCD migration hook.
- [ ] Permify schema version is pinned by callers and evidence.
- [ ] Authoritative tuples are migrated idempotently and validated before application rollout.
- [ ] Permify outage or unspecified decisions deny access.
- [ ] Direct service access is protected; gateway bypass does not bypass authorization.
- [ ] Cross-tenant negative tests pass at gateway and service layers.
- [ ] `traceparent`, request ID, and redacted authorization decision ID propagate across gateway, OPA, Permify, and backend.
- [ ] APISIX admin API is network-restricted and its key is rotated.

**Open local-readiness blocker:** the checked-in security-validation APISIX catch-all does not itself show OPA enforcement, and the application does not currently register the REST payment routes expected by the live gateway tests. These must be corrected before the live gateway gate can pass.

## 7. Redis gate

- [ ] Production uses Redis Sentinel or an approved clustered topology with TLS and authentication.
- [ ] Quorum, master promotion, reconnect, and stale-primary behavior were tested.
- [ ] 2FA reservation uses a single atomic operation and fails closed during Redis loss.
- [ ] Multipart initiation rate limiting is distributed and fails closed when required.
- [ ] Idempotency storage is durable/distributed for multi-replica application deployments.
- [ ] Circuit-breaker trip, topology-change, and failover-duration metrics alert correctly.
- [ ] Complete Sentinel quorum-loss disaster recovery runbook was rehearsed.

## 8. Temporal gate

- [ ] Production namespace, retention, archival, and authentication are configured.
- [ ] Worker task queues and workflow versions are pinned to the release.
- [ ] Workflow retries do not duplicate ledger postings.
- [ ] Activities use idempotency keys and reconcile authoritative TigerBeetle state.
- [ ] Worker restart and Temporal failover preserve workflow state.
- [ ] Temporal/TigerBeetle partial-failure and recovery tests pass.
- [ ] Workflow history and trace IDs are retained for security audit.

## 9. TigerBeetle gate

- [ ] Six production replicas are deployed across approved independent failure domains.
- [ ] Cluster and replica IDs are immutable and documented.
- [ ] Storage volumes meet durability and latency requirements.
- [ ] Double-entry account and transfer invariants pass.
- [ ] Duplicate transfer IDs and invalid balance constraints are rejected.
- [ ] Minority partition and split-brain recovery tests prove zero double-spending.
- [ ] Reconciliation compares PostgreSQL read models with authoritative TigerBeetle state.
- [ ] Backup/restore expectations and disaster-recovery procedures are approved.

A single-node Docker or Kind topology is development evidence only and cannot satisfy the six-replica production artifact.

## 10. Object storage and multipart gate

- [ ] KYC bucket encryption, retention, versioning, access logs, and object ownership are configured.
- [ ] Presigned URLs have bounded expiry and do not appear in logs or traces.
- [ ] Multipart size, content-type, ownership, and tenant-prefix checks are enforced.
- [ ] Concurrent upload completion/abort conflicts are tested.
- [ ] Cleanup CronJob claims work safely and aborts expired uploads.
- [ ] S3 lifecycle policy aborts incomplete multipart uploads after seven days.
- [ ] LocalStack and production-provider integration tests pass.
- [ ] Malware/content scanning and quarantine policy are approved for uploaded documents.

## 11. Observability and incident-response gate

- [ ] OpenTelemetry collectors export traces and metrics to approved backends.
- [ ] OTTL or equivalent sanitization removes tokens, credentials, cookies, payloads, PII, and presigned URLs.
- [ ] W3C trace context propagates through gateway, authorization services, API, workers, Temporal, and storage calls.[1]
- [ ] Prometheus alerts page on authorization dependency failure, 2FA Redis fail-closed events, cleanup failures, backlog, and circuit-breaker trips.
- [ ] Grafana/Datadog dashboards load and display real staging data.
- [ ] Alert routing, escalation, silence, and acknowledgment were tested.
- [ ] Split-brain, credential compromise, tenant escape, and double-spend incident runbooks were rehearsed.
- [ ] Logs and traces have approved retention and tamper-resistance controls.

## 12. Kubernetes and ArgoCD gate

- [ ] Production manifests render without placeholders or mutable image tags.
- [ ] ArgoCD sync waves execute schema migration before tuple migration and application rollout.
- [ ] PreSync/PostSync hooks are idempotent, time-bounded, and observable.
- [ ] Deployments use readiness, liveness, startup probes, disruption budgets, and topology spread.
- [ ] NetworkPolicies allow only required service-to-service paths.
- [ ] Service accounts use least-privilege RBAC.
- [ ] Pods use restricted security contexts, read-only filesystems where practical, and dropped capabilities.
- [ ] External Secrets are `Ready` and materialize required secrets without plaintext Git values.
- [ ] Rollout, rollback, and database compatibility were rehearsed.
- [ ] Admission policy rejects unsigned images, privileged pods, and forbidden registries.

Validate the evidence:

```bash
bash scripts/assurance/run_enterprise_live_validation.sh
python3 scripts/assurance/check_live_go_evidence.py \
  --manifest audit/artifacts/live-go-evidence-manifest.json \
  --repo-root . \
  --max-age-hours 24 \
  --output audit/artifacts/live-go-evidence-check.json
```

The validator rejects static, simulated, fixture, blocked, stale, missing, unhashed, or placeholder evidence.

## 14. Formal approvals

- [ ] Engineering approver records `APPROVE`, name, UTC timestamp, and immutable reference.
- [ ] Product approver records `APPROVE`, name, UTC timestamp, and immutable reference.
- [ ] Security approver records `APPROVE`, name, UTC timestamp, and immutable reference.
- [ ] All approvals reference the same commit, image digest, lockfile hash, release version, cluster context, and evidence manifest.
- [ ] Any manual override includes ticket, justification, requester, timestamp, decision `GO_OVERRIDE`, and explicit runtime-risk acknowledgment.

A manual override does not make missing evidence true; it records accountable acceptance of the remaining risk.

## 15. Deployment execution and rollback

- [ ] Freeze the release commit and image digest.
- [ ] Verify maintenance window and incident commander.
- [ ] Verify backups and restore point.
- [ ] Apply schema-compatible migrations.
- [ ] Execute ArgoCD sync and watch hooks by wave.
- [ ] Confirm Keycloak, APISIX, OPA, Permify, Redis, Temporal, TigerBeetle, PostgreSQL, storage, and OTel health.
- [ ] Run synthetic same-tenant payment.
- [ ] Run cross-tenant denial and forged-header tests.
- [ ] Verify exactly one ledger posting for a concurrent idempotency test.
- [ ] Confirm dashboards, alerts, traces, and audit logs.
- [ ] Observe the release for the approved soak interval.
- [ ] Roll back immediately on authorization bypass, duplicate posting, data corruption, secret exposure, or unreconciled ledger divergence.

## Final decision rule

Production is **GO** only when all required checklist entries are checked, all twelve live artifacts pass the fail-closed validator, the release identity is immutable, and Engineering, Product, and Security approve the identical artifact set. Otherwise the decision remains **NO-GO**.
